# @digitaldefiance/gitdash-give

Add donation choices to an EmDash page and let donors complete checkout on Stripe or PayPal. This native plugin works with both server-hosted EmDash and GitDash sites published to GitHub Pages. It renders ordinary links during the Astro build or page render.

## Embed Stripe checkout on your site

Use **Embedded Stripe donation** in Studio to keep the amount selector and card form on the page. Enter comma-separated whole-dollar presets or use the defaults ($10, $25, $50, $100, $250, and $500). Donors can also enter their own amount in USD. Card issuers can still prompt for authentication. The existing **Donation choices** block can be used for hosted Stripe or PayPal links.

The site can stay on GitHub Pages. Deploy the included session handler as a Cloudflare Worker from any project with this package installed. For example, create `worker/donate-worker.mjs` in your site repository:

```js
export { default } from "@digitaldefiance/gitdash-give/stripe-worker";
```

Point a Wrangler config at that file and set `DONATION_NAME` and `DONATION_RETURN_URL` under `[vars]`. The return URL must be an HTTPS page on the exact origin that embeds the form. The example below applies an optional per-IP limit to protect calls to Stripe. Choose a rate-limit namespace ID unique in your Cloudflare account.

```toml
name = "site-donations"
main = "donate-worker.mjs"
compatibility_date = "2025-01-01"

[vars]
DONATION_NAME = "Donation to Example Charity"
DONATION_RETURN_URL = "https://example.org/donate/"

[[ratelimits]]
name = "DONATION_RATE_LIMIT"
namespace_id = "20461"

[ratelimits.simple]
limit = 20
period = 60
```

Store `STRIPE_SECRET_KEY` as a Worker secret. Provide `PUBLIC_GIVE_STRIPE_PUBLISHABLE_KEY` and `PUBLIC_GIVE_STRIPE_SESSION_URL` to Astro at build time. The session URL is the Worker’s HTTPS URL followed by `/create-checkout-session`. Use matching Stripe test keys to verify the payment in Stripe before switching both keys to live mode. The Worker creates sessions on demand when the donor continues to payment. Use the Stripe Dashboard to verify donations and manage receipts.

To migrate an imported GiveWP shortcode to this block, pass `{ embeddedStripe: true, presets: "10, 25, 50, 100, 250, 500" }` for its form ID in `migrateGiveWpBlocks`. Existing maps containing hosted checkout links still work.

## Set up checkout

Create a Stripe Payment Link for each fixed amount you want to offer, or create a link that lets the donor enter an amount. For PayPal, copy the link from a hosted Donate button. Use the public links generated by the provider. [Stripe Payment Links](https://docs.stripe.com/payment-links/create) · [PayPal Donate buttons](https://www.paypal.com/donate/buttons)

The plugin accepts these URL formats.

| Provider | Format |
| --- | --- |
| Stripe | `https://buy.stripe.com/<link-id>` or `https://donate.stripe.com/<link-id>`, including Stripe test links |
| PayPal | `https://www.paypal.com/donate/?hosted_button_id=<button-id>`, including the corresponding `www.sandbox.paypal.com` link |

Use a Stripe URL without query parameters, or a PayPal URL with only `hosted_button_id`. Each choice needs a label, such as **Give $25** or **Choose an amount with PayPal**. The renderer skips invalid and duplicate links.

Provider checkout handles amounts, payment details, and confirmation. Configure receipts and any return page in the provider dashboard. Keep donor details and donation history in the provider dashboard or a private archive.

## Add the donation block

Pack the plugin from a sibling checkout and install it from the site root. Keep the tarball and npm lockfile in the site repository so GitHub Actions can install the same package.

```sh
mkdir -p vendor
npm pack ../gitdash-plugins/packages/give --pack-destination vendor
npm install ./vendor/digitaldefiance-gitdash-give-0.1.0.tgz
```

Import `givePlugin` in `astro.config.mjs` and add `givePlugin()` to the existing `plugins` array passed to `emdash()`.

```js title="astro.config.mjs"
import { givePlugin } from "@digitaldefiance/gitdash-give";
```

On a GitDash site, add `giveStudioPlugin()` to the `plugins` array of `globalThis.__STUDIO_PLUGINS__`. Load the configuration before the studio boot script. If the site has no studio plugin configuration, start with this file.

```ts title="src/studio-plugins.ts"
import { giveStudioPlugin } from "@digitaldefiance/gitdash-give/studio";

(globalThis as typeof globalThis & { __STUDIO_PLUGINS__: unknown }).__STUDIO_PLUGINS__ = {
	plugins: [giveStudioPlugin()],
	admins: {},
};
```

In the page editor, open the slash menu in a Portable Text field and select **Donation choices**. Add each checkout link with its visible label. Publish the page, then verify that each link opens the intended campaign and amount in the provider's checkout. Supply translated editor labels through `givePlugin({ labels })` or `giveStudioPlugin(labels)` when the site's editors use another language.

## Render choices from an Astro page

Use the component directly when the donation page is defined in Astro. Replace the example test URL with a link from your provider.

```astro title="src/pages/donate.astro"
---
import Donate from "@digitaldefiance/gitdash-give/Donate.astro";
---

<h1>Donate</h1>
<Donate choices={[{ label: "Give $25", url: "https://buy.stripe.com/test_EXAMPLE" }]} />
```

## Migrate a GiveWP page

1. Import the WordPress page into EmDash and keep its existing URL and page copy. Use the published GiveWP form settings to recreate its amounts and currency in your checkout provider. The WordPress XML export may omit the GiveWP settings.
2. Replace the `[give_form id="…"]` shortcode or GiveWP Donation Form block with **Donation choices**. In a fixed-price checkout, create one link per preset. Add a separate custom-amount link if the original form offered one.
3. Test a donation in the payment provider's test environment and verify the confirmation and receipt. Swap in live links before publishing.
4. Keep any existing GiveWP donations, donor history, receipts, or subscriptions available privately through the old system or a secure export. Update links to the old receipt and donor dashboard pages according to where donors can access that history. The plugin's links open provider checkout and do not carry over historical records.

For a scripted import, pass the imported Portable Text field and a map from WordPress form IDs to checkout choices to `migrateGiveWpBlocks`. Save the returned `content` through your site's existing content import or edit path after resolving any `unresolvedFormIds`. The helper converts standalone legacy shortcodes and GiveWP Donation Form blocks. It preserves the existing Portable Text block key and leaves surrounding content intact.

```js
import { migrateGiveWpBlocks } from "@digitaldefiance/gitdash-give/wordpress";

const { content, unresolvedFormIds } = migrateGiveWpBlocks(importedPage.content, {
	1027: [{ label: "Give $25", url: "https://buy.stripe.com/test_EXAMPLE" }],
});
```
